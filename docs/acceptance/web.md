## 自动化交互证据

测试通过 Testing Library + user-event 驱动真实 React 组件，服务使用清晰标记的内存 demo；失败/过期场景用契约 DomainError 注入，不作为后端数据库测试证据。

1. 保存故障保留编辑输入，未误显示已保存，显式重试成功。
2. 多标签模拟旧修订保存被拒绝；读取服务器草稿、保留本地输入并以新修订保存。
3. 未保存不能提交；保存后提交固定修订、说明与幂等键。
4. 作者即使是管理员也无法自审。
5. 三方冲突可选内容，新建草稿并撤回旧提案。
6. 非作者维护者必须勾选最终预览，批准调用使用服务 token/currentVersion/revision。
7. 保留原版与使用新版分别传递正确目标与偏好修订；原任务快照前后完全相等。
8. 过期目标刷新状态并提示重新确认，仅调用一次 setPreference。
9. 接受任务记录固定版本，页面明确当前任务不变。
10. 列表搜索、详情、历史、两个版本差异可操作。
11. 加载失败可重试，重试后空态清楚。
12. 冲突解决期间基线变化时不保存、不撤回，手动解决输入保留，重新比较后仍保留。
13. 冲突选择不存在资源表示删除，没有生成空文件。
14. 请求修改后的作者可继续编辑、保存、重新提交，旧提案 withdrawn、新提案 pending。
15. 未改内容时禁用提交。
16. changes_requested 可以比较，但维护者不能直接批准。
17. 停止输入后自动保存，并可从服务读回最后成功保存内容。

## 契约假设与明确剩余工作

- D1–D3 是待产品确认的默认值：选择只影响后续新任务；按会话/技能保留旧版直到解除；未处理提示时新任务默认最新。UI 有可展开说明，运行时提供真实持久化/并发保证。默认规则若改变，需要同步服务配置与 UI 文案。
- 按协调端确认，previewMerge 对作者或该 Skill 维护者开放，允许 pending / changes_requested / conflicted；reviewProposal 与 mergeProposal 只允许 pending 且非作者维护者。共享契约未自行修改。
- 服务最终校验身份、授权、草稿修订、内容及幂等；前端按钮禁用不能代替服务授权。接入时 Actor 必须来自宿主认证，不能信任浏览器输入。
- 独立入口的任务链只是接受任务、解析技能包、记录已解析调用，未执行真实 LLM/Agent。必须在阶段 2 接入宿主真实任务生命周期，不能把前端按钮行为当作平台接受/执行证据。
- 没有首次创建 Skill 表单、维护者配置 UI、持久会话路由、历史会话/任务恢复入口。App 接受 initialSessionId，但路由、刷新恢复和会话列表由后续宿主接线补齐；演示刷新重置。完整 M1/M2/M5 并未宣称完成。
- 当前仅操作后刷新、返回页面重新加载和手动刷新；没有订阅、通知中心或外部通知，也未接入实时推送/断线重建/多标签同步。getSessionUpdates 应持续提供已保留的版本状态，前端才能持续呈现其标记。
- 未接真实 LibraryService/RuntimeService：数据库原子性、任务接受与偏好的跨模块顺序、资源保留、广播补偿、真实身份、Agent 执行、性能容量、审计与备份都留待阶段 2/3 验收。
- 冲突解决是创建/保存新草稿、撤回原提案、提交新提案的多步流程；v1 无事务式解决接口，失败可能留下未提交草稿。不会自动覆盖新基线或复用旧批准。需宿主后续提供草稿列表/恢复管理以改善中断恢复。
- 支持 UTF-8 文本资源和安全原文呈现，不支持二进制上传、脚本执行或富 Markdown 渲染；格式/构建通过不能代表 Skill 效果验证。
