# Skill Library 开发编排与合并计划

用户在当前 main 工作区管理开发及合并。所有应用源码、测试、依赖清单、锁文件和运行配置放在 src 下。开发模块使用独立 worktree，完成后提交并保留，不自动合并或推送。

## 技术基线

已确认 TypeScript、React、Node.js、SQLite。采用独立模块 package.json 和锁文件，避免并行修改公共依赖。src/contracts 是管理端唯一维护的模块边界；前端依赖接口，不依赖后端具体实现。未提供真实 Agent 平台和身份接口，本轮使用明确的适配器边界，不将演示称为生产接入。

## 开发顺序

| 阶段 | 工作 | 启动条件 | 完成与合并门槛 |
| --- | --- | --- | --- |
| 0 共同基线 | 需求、目录规范、共享契约、任务书 | 立即 | 管理端提交基线，所有 worktree 从同一提交创建 |
| 1A 管理服务 | M1、M2 数据与历史、M3、M4、M7 校验审计 | 基线就绪 | SQLite 真实持久化、权限、提案、冲突与原子合并测试通过 |
| 1B 任务运行时 | M5、M6 会话策略及提示重建 | 基线就绪 | 通过 Host 接口隔离服务依赖，固定版本、子任务、恢复、会话策略测试通过 |
| 1C 前端交互 | M2 至 M6 用户界面 | 基线就绪 | 通过接口注入和明确演示适配器独立运行，关键交互测试与构建通过 |
| 2 组合接线 | HTTP 服务与客户端、身份适配、事件推送、开发启动与种子数据，以及首次创建、维护者配置和会话恢复等剩余界面 | 用户审阅并合并 1A、1B、1C | 真实模块联调，跨模块一致性、故障补偿与端到端用例通过 |
| 3 平台验收 | 真实 Agent 与身份集成、容量、备份恢复 | 平台接口提供，D1 至 D6 定稿 | 需求文档 E1 至 E15 通过，真实 Agent 验收及性能证据齐备 |

第一阶段三个任务相互不依赖，可并行。它们是工程交付单元，不等同于需求文档 M1 至 M7 已全部完成。尤其 M6 的实时推送与 M7 的运维验收留到阶段 2、3。

## 第一阶段任务书

### A 管理服务

实现 LibraryService 及可关闭的 SQLite 持久化工厂。覆盖角色权限、团队隔离、非作者维护者评审、独立草稿与修订保护、不可变提案、历史版本、正文及资源差异、三方合并预览与确认、并发保护、幂等合并、持久化事件及审计。参考 M1 至 M4、M7；严格遵守 contracts/README 的语义。

完成条件：模块安装、类型检查和测试通过；两个独立数据库连接竞争合并不丢更新；进程重启可读取版本与事件；合并事务故障回滚测试；跨团队、自审、旧修订、旧预览和重复提交测试；完整记录无法覆盖的生产集成项。

### B 任务运行时

实现 RuntimeService 和 RuntimeHost 适配接口，SQLite 持久化会话、任务快照、调用、偏好。验证任务接受时版本固定、子任务继承、同 ID 重试与恢复幂等、资源校验、真实调用后提示重建、会话偏好并发及过期目标保护。不得实现或假装已经接入真实 LLM/Agent。

完成条件：模块安装、类型检查和测试通过；v1 任务在 host 切到 v2 后仍解析全部 v1 资源；新任务用 v2；重开数据库可恢复原快照；权限和不存在资源拒绝；连续更新、无事件重建、保留旧版和重新跟随新版测试通过。报告 host 快照与偏好串行化的边界和阶段 2 所需约束。

### C 前端交互

实现 React 应用，注入 LibraryService、RuntimeService 与 Actor。中文界面包括列表、详情、历史、编辑草稿、提交修改、维护者评审、三方冲突呈现及解决入口、会话任务与更新提示、保留旧版或使用新版。演示适配器仅用于本模块开发，必须明显标记，不作为后端测试证据。

完成条件：可独立启动；构建、类型检查和关键交互测试通过；保存失败保留输入；过期修订可恢复；自审操作不可用且反馈清楚；更新提示说明当前任务不变；选择新版/旧版调用正确接口；加载、错误、空态、窄屏可用；无订阅功能。记录浏览器检查结果，未执行的检查明确标注。

## 验收报告格式

每个 worker 在指定报告写明：范围；实现与需求映射；准确的安装、运行、测试命令；实际通过/失败数量；关键场景证据；未验证项；接口假设；提交 SHA（可在最后报告中补充，避免自引用）；合并注意事项。提交仅包含自己拥有的文件。

模块完成后的状态为“模块验收通过，等待用户合并”，不能写成“项目上线完成”。保留 worktree 与分支供用户管理。主分支不自动吸收模块代码。

## 合并与后续启动

建议合并顺序 A → B → C，便于按数据、执行、界面逐层检查；三者基于同一契约且目录不重叠，可独立审阅。每次合并前核对文件所有权、运行该模块测试并检查 git diff --check。全部合并后再启动阶段 2，集中接线，避免各模块在未知实现上重复搭建 server 或 client。

阶段 2 启动前核对 D1 至 D6，尤其会话选择生效时间和未选择默认行为。当前开发以需求文档建议默认值实现可配置边界，不视为产品决策已经确认。

阶段 2 还要逐项对照模块报告补齐未覆盖的用户入口，不能仅增加 HTTP 包装就宣告全部需求完成。预计包括首次创建 Skill、维护者配置、持久会话路由和恢复入口；开始任务时明确授权相应 worker 修改已有 web 模块。真实身份成员选择、二进制资源、平台内容规范和任务生命周期仍依赖产品或平台契约。
