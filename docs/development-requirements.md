# Skill Library 开发需求 v2

本版为当前有效需求，替代 v1 中的人工评审与维护者事后合并流程。用户已确认：修改提交后自动批准生效；只在正式生效后广播；编辑者在自己的草稿中处理与新版的差异。历史需求留存于 archive/development-requirements-v1.md，不再作为审批流程的验收依据。

## 1 已确认的产品行为

- 面向非技术用户，Skill 在已有线上 Agent 平台使用。
- 使用、修改、历史版本和更新处理是核心操作；没有待评审列表、请求批准或管理员冲突处理。
- 作者独立编辑草稿；保存不生效。点击“提交并生效”后通过系统校验即产生正式版本。
- 自动批准不绕过授权、内容校验、版本检查或幂等保护。
- 正式生效后统一广播，草稿保存和更新处理不产生发布通知。不设计订阅通知功能。
- 编辑同一 Skill 的用户收到更新提示与差异入口。提醒不能覆盖编辑内容，不能清除未保存输入。
- 作者必须手动确认如何处理自己的修改与新版之间的分歧；即使没有文本冲突，也必须明确确认同步到新基线。
- 过期草稿可继续编辑和保存，但不能发布。服务端必须拒绝基线过期的发布，不在发布阶段偷偷合并。
- 正式版本及完整资源不可变，历史恢复以新草稿重新发布，不改写历史。
- Agent 正在进行的任务、子任务、自动重试和恢复仍固定原版本。新任务默认最新版。

## 2 编辑与更新流程

1. A、B 从 v1 创建独立草稿。
2. A 提交，系统校验通过后 v2 生效，写入发布事件并广播。
3. B 编辑区提示“此技能已有新版本，你的修改已保留”。B 可以继续编辑，或查看更新。
4. 对比展示基础内容、我的修改、团队最新版、双方差异及合并候选。预览包含本地尚未保存的输入。
5. B 对重叠修改选择采用新版、保留自己的版本、手动编辑或明确删除文件。非重叠改动可以预填候选，必须确认后应用。
6. B 确认后，系统原子保存处理结果和新的草稿基线，递增草稿修订；此操作不发布、不广播。
7. B 点击“提交并生效”，系统再次核对基线、修订和内容，通过后产生 v3。

如果 B 处理期间又出现 v3：旧预览不再能直接应用；保留编辑输入和已作选择，要求重新查看最新差异。若处理预览后本地又发生编辑，也不能用旧预览覆盖后来的输入。

## 3 用户操作与权限

| 操作 | 权限和结果 |
| --- | --- |
| 使用、查看历史 | 团队内有访问权限的用户 |
| 新建、修改、提交并生效 | 有编辑权限的用户；草稿仅作者可读写 |
| 查看更新、应用处理结果 | 该草稿作者；不需要其他人审批 |
| 维护者配置、团队审计 | 既有管理员权限保留，不参与内容批准或冲突合并 |

不再要求存在另一位维护者才能创建或发布 Skill。维护者可作为负责人和已有编辑授权信息保留，但不是审批人。历史版本中的真实评审信息保留；新版本标记自动生效，不能伪造一个人工评审者。

## 4 关键一致性规则

### 4.1 发布

发布请求携带草稿修订、预期基础版本、说明与幂等键。服务端在同一事务中核对草稿作者、权限、修订、基础版本与当前正式版本；全部一致且内容有效才允许发布。

同一事务写入：新不可变版本、当前版本指针、发布审计、持久更新事件、幂等回执，并将发布者草稿基线推进到新版本。任意一步失败全部回滚。请求超时后原请求重试只返回同一个版本，不重复发布或广播。

两人同时从同一基础版本发布，只能一个成功。另一人收到“有新版本待处理”，保留草稿后进入作者更新流程；即使修改不同段落，也不得由服务端直接合并发布。

### 4.2 草稿与预览

保存允许临时不完整文本，如正文暂时为空或引用待补齐，但仍校验资源路径、类型、大小与权限。完整包检查在发布时执行。

预览绑定作者、团队、草稿修订、原基线、本地输入快照和目标版本，不能混用其他草稿或其他人的预览。应用时再次核对目标和修订，以一个事务更新内容及基线。

自动保存、远端响应与预览应用必须协调：不能把旧保存响应当成当前编辑内容，不能让旧自动保存覆盖新处理结果。广播只更新提示信息，不直接改草稿正文或基线。

### 4.3 广播与恢复

仅持久化发布事件进入广播通道。按团队隔离，前端筛选与当前编辑 Skill 或实际调用过的会话相关的事件。

在线编辑者收到提示；重复、乱序和连续发布只保留最新有效提醒。页面打开、刷新和重连时重新查询当前正式版本，即使漏掉广播也能发现过期草稿。

无订阅开关、通知中心或外部消息。草稿同步确认不广播，失败提交不广播，幂等重试不产生第二个逻辑发布事件。

### 4.4 任务隔离

运行时已有任务快照机制不变。广播、作者同步草稿、自动批准和会话版本选择均不能改写已经接受的任务版本。真实 Agent 生命周期和跨库任务接受一致性仍需专门集成验收。

## 5 本次开发模块与完成条件

| 模块 | 开发任务 | 完成条件 |
| --- | --- | --- |
| 管理服务 v2 | 去除人工审批入口；直接发布；作者差异预览与原子同步；兼容已有数据 | 作者可独立发布；过期基线拒绝；两连接竞态、幂等、回滚、旧数据保留、越权测试通过 |
| 编辑界面 v2 | 移除评审导航和批准操作；发布按钮；实时更新横幅；三方差异与作者处理；未保存输入保护 | 发布后显示生效状态；更新不覆盖输入；无冲突也要求确认；连续发布、预览后输入变化、删除和保存竞态交互测试通过 |
| 广播适配层 | 持久事件到 HTTP/SSE；可信身份接口；浏览器客户端；重放与重连 | 两客户端真实传输；仅正式发布事件；跨团队隔离；掉线补发；旧审批接口不可调用 |
| 组合验收 | 在独立测试环境组合真实管理服务、广播层和前端客户端 | A 发布→B 收到→B 预览与确认→B 发布闭环有实际证据，不以纯演示替代 |

全部应用代码、测试、依赖和运行配置位于 src。模块在独立 worktree 开发并提交，用户管理正式合并；管理端可在临时验收环境组合模块进行测试，不合并到 main。

## 7 保留的范围与待确认项

已有团队隔离、审计、历史版本、文本资源限制和运行时版本策略保留。本次不扩展到二进制资源、真实模型执行、完整团队管理、容量或线上部署。

会话版本选择暂定只影响后续任务；保留旧版仅对当前会话有效；未选择默认新版。这些原有待确认项不因自动批准而自动定稿。已确认的新行为“自动生效、仅生效后广播、作者处理冲突”不再列为待确认。
