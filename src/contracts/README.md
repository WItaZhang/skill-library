# Shared contract v2

This contract supersedes v1 human review/merge behavior. User confirmed immediate automatic approval and broadcast only after publication. Runtime task/version isolation is unchanged. Old Proposal/Review/Merge types are legacy storage vocabulary only: LibraryService no longer exposes those operations and transports MUST NOT route them.

## Publication

publishDraft(actor, {draftId, expectedRevision, expectedBaseVersionId, changeSummary, idempotencyKey}) is the sole publication operation. Require draft ownership and current editing permission, correct revision, and equality of draft.baseVersionId, expectedBaseVersionId and Skill.currentVersionId. Outdated drafts ALWAYS fail STALE_REVISION, including text changes which would be automatically mergeable. Do not rebase or merge inside publication. There is no second-person reviewer requirement. Maintainers are optional metadata/editors, not approvers; creating a Skill must not require another user. Keep role/team security.

Validate the complete package on publication. Atomically write immutable version, current pointer, publication audit, durable update event and idempotency receipt, then advance the publishing draft base to that new version and increment its revision. New versions use reviewerId:null and approvalMode:'automatic'; old published records remain byte-for-byte unchanged. Exact successful retries return the original version even if the draft has since advanced; same key with different payload fails. No event for saves, previews, synchronization, failed publication or duplicate success replay.

## Author-controlled draft update

previewDraftUpdate accepts the editor's current content including unsaved input, with expected saved draft revision. It returns base, local, latest, both sets of diffs, a three-way candidate, explicit conflicts, current target version and a server-issued token. Author-only, team-scoped. It must not change saved draft content, revision or base. The token binds actor, team, draft revision, original base, local input digest, target and preview snapshot. Every preview may be stored for integrity/recovery without changing the draft.

applyDraftUpdate is explicit author confirmation. In one transaction validate token/ownership, unchanged draft revision and still-current target; persist resolvedContent and target base together and increment revision. No publication or event. A token for an older target is invalid even if changes seem non-conflicting. Preserve all inputs on rejection; never silently substitute a new target. Resolved content is author's explicit decision; conflicts must be explicitly resolved in UI including file deletion versus empty content. The server validates draft structure, not an implied approval by a maintainer. Same successful request retry returns the original synchronized draft; different payload same key fails.

Draft saving/updating must permit incomplete textual work (e.g. temporarily empty SKILL.md or unresolved local reference) while retaining path, type, size and ownership protections. Strict publish validation remains the final gate. Preview receives an immutable copy of local input. If the editor changes after preview, invalidate apply until refreshed or explicitly incorporate those changes; in-flight responses must never overwrite newer typing. Broadcast only changes update metadata, not editor contents or base. Auto-save cannot race synchronization and overwrite its result.

When opening/reconnecting an editor, compare its saved base with current Skill version even if no event was received. Ongoing editing/saving is allowed while outdated; publication is blocked until author confirmation. Multiple publications coalesce to the latest relevant version; preserve manual resolution choices on target change and show they require rechecking.

## Broadcast and transport

SkillUpdateSource delivers committed SkillUpdateEvent only; it is not a subscription product or notification center. Subscribe across the authenticated team, and web filters to its currently edited Skill or actually used session Skills. onReconnect fires on every successful connection, including initial, so consumers reconcile authoritative current state. Event delivery may duplicate or arrive late; consumers never mutate drafts based on event payload alone. Unsubscribe on unmount/identity change. Cross-team event payloads must never be exposed.

Broadcast module owns HTTP adapters: POST /api/library/<LibraryService method> with JSON {args:[...arguments except actor]}, server supplies Actor via mandatory trusted resolveActor callback. Never route arbitrary object properties, legacy review/merge methods, or accept body Actor. GET /api/events?after=<sequence> uses SSE with event skill.updated, id=sequence, JSON event data; honor Last-Event-ID, replay durable service events and continue polling for external-process publications. Native EventSource client authenticates via same-origin cookies/host; no production demo identity fallback. Transport errors use shared DomainError codes. Require same-origin/allowed-origin policy for POST and custom X-Skill-Library: 1 header; do not enable wildcard credentialed CORS. Tests inject explicit identities; production auth remains host-owned.

Export broadcast module createLibraryHttpHandler({library, resolveActor, ...optionalConfig}), createHttpLibraryClient({baseUrl?, fetch?}), and createSseSkillUpdateSource({baseUrl?, ...optionalConfig}). They must not import concrete service/web/runtime implementations. Service/runtime factories retain their v1 export names; web App gains optional updateSource injected prop (connected integration must provide it), library/runtime/actor remain injected.

## Persistence and unchanged runtime rules

SQLite existing v1 version data must be preserved on schema initialization/migration. Retired pending proposals may remain as historical data but cannot publish through old operations. Document how an old draft can continue through v2. Full text resources and canonical SHA-256 retain v1 format: sorted path ascending, JSON objects with keys path, content, mediaType in that order, UTF-8 bytes, lowercase hex. SKILL.md mandatory on publication; binary resources remain out of scope of this change.

Runtime tasks pin complete Skill version mapping, children/retries/recovery preserve it. Provisional D1-D3 session defaults stay unchanged. RuntimeHost catalog/preference/task cross-store ordering remains a previously documented integration constraint; do not claim this change fixes it. Real Agent/production identity and remaining unrelated management UI are not part of this scoped revision.
